# 漫频 Aether 体验规划草案

更新日期：2026-10-24。三页及其视觉分工已确定；以下具体行为仍为讨论稿，不是已批准的完整 UI 规格。

**Aether 是视觉体验特化项目。** 第一页为图一／图二方向的纯沉浸播放；第二页为图三方向的复古调节；第三页为图四方向的现代主页面，上部增加同款蓝色显示屏，用于可筛选电台的展示与选择，并承载设置。

当前先整理[页面元素](PAGE-ELEMENTS.md)。导航结构、横竖屏布局、具体控件映射、配色数值、字体、图标和动效尚未确定。[原始视觉参考](../design/references/README.md)属于已确定的方向依据。

## 三页的体验分工

- **沉浸播放**：让用户停留观赏和聆听。主视觉优先，关键信息与少量操作克制出现。
- **复古调节**：让用户感受成组设备、旋钮、按键与仪表的操作层次。按键可以丰富，实际动作仍围绕电台收听。
- **现代主页面**：承担清晰查找、筛选、选择电台与设置，是默认主入口。上部屏幕与下部控制台的关系由用户确定。

建议三页操作同一个播放状态，切换表现方式时保持当前电台与声音连续；这项行为建议仍需在后续交互细则中明确。

## 用户想完成的事

| 场景 | 用户意图 | 需要提供的内容与动作 |
| --- | --- | --- |
| 已知目标 | “我要听 FM 802” | 直达搜索、匹配依据、同名台的地区区分 |
| 按范围找台 | “想听日本的爵士台” | 国家／地区、类型和语言筛选，清晰显示当前范围 |
| 返回常听 | “回到我收藏的台” | 个人收藏、个人置顶、明确的当前播放标记 |
| 随机探索 | “带我去一个未知频道” | 主动随机调频、目标电台身份、连接结果 |
| 正在收听 | “这里在播什么、声音来自哪里” | 电台身份、播放状态、可用的节目名与当地时间 |

## 直达搜索

需求目标是一个统一入口接收名称、城市和呼号，输入时更新结果。需要讨论的行为包括：

- 忽略大小写和常见空格、标点差异，例如 `FM802` 与 `FM 802`。
- 通过已确认的别名关联中文名、英文名和呼号。
- 结果显示匹配依据，不把地理邻近或人气伪装成文本匹配。
- 同名电台以国家／地区和已知城市区分。
- 清空关键词、组合筛选、无结果与离线目录分别有明确行为。
- 输入改变后不让旧请求的结果覆盖新查询；不在每次键入时触发播放。

搜索结果的固定顺序或匹配优先级待用户确认。城市与呼号的数据补充方式也待确定。

## 分类与收藏

已提出的查找维度为国家／地区、音乐风格／节目类型和语言。建议组合筛选可以清除，并清楚说明当前范围。

收藏属于用户自己的选择。收藏与取消应当直接可达，个人置顶不转化为公共推荐。是否需要自建分组、手动调整顺序或最近收听，留待确认。

电台实体与音源记录建议区分：同一台的不同码率或备用地址可以成为音源选项；地方频道或不同节目版本不应仅凭相似名称合并。此规则仍需结合目录数据讨论。

## 播放与状态

建议区分下列状态，并以实际播放器事件驱动：

| 状态 | 用户需要知道的事 | 动作草案 |
| --- | --- | --- |
| 未播放 | 当前没有收听 | 选择电台或开始播放 |
| 正在连接 | 已接收选择，正在连接音源 | 允许取消或改选 |
| 正在缓冲 | 正在准备或恢复声音 | 呈现等待状态，保留用户控制 |
| 正在播放 | 音频确实处于播放状态 | 暂停、收藏或切台 |
| 已暂停 | 用户主动暂停 | 再次播放；恢复策略待定 |
| 播放中断 | 网络、音源或系统事件影响了收听 | 说明状态，重试策略待定 |
| 无法播放 | 本次连接失败 | 重试、其他音源或返回目录，取决于已确定能力 |

`LIVE` 表达直播属性，不能代替播放状态，也不表示零延迟。暂停时是否释放连接、恢复时是否返回直播点，尚未确定。助理此前提出过“释放连接并回到直播点”，目前仍为建议。

切台时建议立即清除旧台的节目文字，连接结果只归属于当前选择。无台标、无节目名或未知码率都应当是正常内容状态，不阻断可用音源播放。

## 随机调频

已确定随机探索需要由用户主动触发。以下行为仍为建议：

- 可在当前筛选范围与全球范围之间选择。
- 按电台实体抽样，避免多音源记录增加同一台的抽中概率。
- 不以点击量、收藏量或商业权重参与抽样。
- 连接失败后允许继续尝试，并提供取消入口。
- 保留返回上一个电台的能力。

城市、时间、类型组成的短句只能使用已知信息。“来自东京的夜间爵士”需要可靠地点、当地时间和类型标签；它不应被解释为真实节目单或此刻曲目的判定。

## 信息的可信表达

- 电台所在地与音频服务器所在地分别处理。
- 时钟依赖可靠时区，日夜判断另需可靠位置；不能由国家猜测。
- 目录记录的码率不直接等同于当前实际解码码率；未知值不填默认数字。
- 连接质量依据网络播放表现，音频电平依据真实音频；两者不能混用。
- 节目元数据为空或乱码时需要降级；是否记录其更新时间，留待信息层级讨论。
- 长标题的完整可读性保留为目标；滚动字幕的速度、触发方式和减弱动画方案留给 UI 阶段。

## 下一阶段的讨论顺序

1. 按三页既定视觉目的，确定各页必要元素、次要信息与控件候选。
2. 明确候选功能取舍、公共目录与搜索排列规则、复古控件映射及设置范围。
3. 确定三页切换、播放／暂停、随机调频和异常状态的交互行为。
4. 沿已确定的参考方向细化原创 UI、横竖屏和动效。

后续验证由自动枚举、行为回归和实际界面检查组成；具体设备、网络地区与测试范围随实现阶段记录。
