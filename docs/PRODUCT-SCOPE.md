# 漫频 Aether 产品范围

更新日期：2026-10-24。现代与沉浸两页视觉状态已冻结并授权同步仓库，进入 Kotlin Android 实现。当前仍是浏览器视觉样机，尚未接入真实电台播放或创建 Android 工程。

本文件区分用户已提出的需求、具有数据条件的展示目标，以及助理提出但尚未确认的建议。“需求”不等于“已实现”。

## 产品定位与原则

漫频 Aether 是专注声音纯粹性与视觉美学的独立电台 App。**项目以视觉驱动，特化视觉体验，不以全能功能为目标。** 用户通过搜索、分类、个人收藏与主动随机调频决定收听内容；功能的取舍要服务于页面体验。

已确定的原则：

- 应用不投放广告。
- 中立索引，不做算法推荐或信息流干预。
- 不做人气榜、精选榜、商业置顶或推荐排名。
- 两个主页面：现代主页面与纯沉浸播放；早期复古第三页撤出本轮范围。
- 现代页是主页面；最新下部为银灰控制台，上方左侧为仪表与绿色频谱、右侧为银灰大屏，用于筛选和选择电台，并提供设置能力（更新早期同款蓝屏方向）。
- 两页共用电台、播放状态与连接；设置只在现代页进入。最新要求以左右滑动切换现代／沉浸视图，沉浸页上下滑动与两枚三角切台，没有播放／暂停、菜单或设置。设置只需语言、更新检查和 About。
- 现代页以墨水屏和实体控制为核心：四键、双旋钮、默认墨水材质与统一灯光；关机短暂刷新后保留显示内容。小旋钮具体映射尚未最终确认。
- 用户已要求记录当前两页状态并同步 GitHub 备份，随后以 Kotlin 构建 Android App。
- 先围绕已确定的视觉方向规划页面元素，再细化交互与原创视觉稿；不为填满控件扩充功能。
- 电台播放测试由后续自动枚举与回归承担；不要求用户先维护样本表或手工逐台测试。

“不做排序”是用户原始表述。公共目录采用什么固定排列规则、搜索是否允许按匹配程度排列，仍需确认；不能将助理建议的字母／拼音顺序当作已决定事项。个人收藏中的用户置顶与公共排名分别讨论。

两页视觉分工见[视觉方向](../design/README.md)，逐页内容与控件候选见[页面元素](PAGE-ELEMENTS.md)。这两页是不同用途的界面，不只是同一页的三套颜色主题。

## 用户已提出的核心信息

| ID | 信息 | 产品目标 | 数据缺失时的处理建议 |
| --- | --- | --- | --- |
| R01 | 电台名称 | 明确正在浏览或收听哪个台 | 保留来源标识，避免空白名称；具体补救规则待定 |
| R02 | 电台标志 | 优先呈现电台本身的视觉身份 | 统一文字占位；不因台标缺失阻断播放 |
| R03 | 播放／暂停状态 | 清晰的操作反馈，加载与缓冲可感知 | 连接失败独立表达，不能伪装成正在播放 |
| R04 | 国家／地区 | 明确声音所属的国家或地区 | 未知就保持未知，不由语言猜测 |
| R05 | 直播标识 | 区分直播电台与普通音乐文件 | 直播属性与当前实际播放状态分别表达 |

台标目标为官方视觉标志，但目录中的 `favicon` 本身不构成“已验证官方”的证明。缺失处理是体验建议，尚未确定具体视觉形式。

## 用户已提出的查找与探索功能

| ID | 功能 | 范围 |
| --- | --- | --- |
| R06 | 直达搜索 | 支持电台名称、城市、呼号，输入时更新结果 |
| R07 | 国家／地区浏览 | 包括中国大陆、香港、日本、美国、德国、澳大利亚等；具体列表待整理 |
| R08 | 类型与语言分类 | 音乐风格、新闻／谈话等节目类型，以及播出语言 |
| R09 | 我的收藏 | 一键收藏、快速调取，支持用户个人置顶 |
| R10 | 标签跳转 | 点击电台类型或流派标签，查找同类型电台 |
| R11 | 随机调频 | 用户主动触发，探索未知电台；具体抽样范围与失败行为待确认 |

搜索目标包括别名、城市与呼号，但不承诺底层 API 已经具备完整字段。Radio Browser 的标准字段包括名称、国家／地区、州／地区、语言和标签，并没有完整独立的城市、呼号、时区字段。数据补充与索引策略是后续工作。

## 用户已提出的附加信息

| ID | 信息 | 展示条件与待确认边界 |
| --- | --- | --- |
| R12 | 当前曲目／节目名 | 音源实际提供元数据；保留完整原文，长文字展示方式留给 UI 设计 |
| R13 | 码率与编码 | 有可靠信息时展示，例如 `128 kbps AAC`；来源目录值与实际解码信息需区分 |
| R14 | 流派与节目标签 | 有标签时展示；标签描述电台分类，不必然描述此刻正在播出的内容 |
| R15 | 信号／连接质量 | 目标为可感知的网络播放状态；建议以缓冲、重连等可测表现为依据 |
| R16 | 当地时间与日夜 | 有可靠城市、时区和位置数据时展示；不能把国家直接等同于单一时区 |

连接质量、电平与直播延迟具有不同含义。建议网络质量对应连接状态，VU 表对应真实音频电平；没有测量依据时不显示精确丢包率或端到端节目延迟。此处记录数据表达建议，尚未选择表盘、信号格、指针或动画方案。

## 尚未确认的候选能力

以下来自助理建议，不视为用户已批准的首版范围：

- 最近收听与本地记录清理。
- 睡眠定时。
- 自定义电台链接。
- 收藏分组及更完整的个人整理方式。
- 同一电台多音源合并、音质选择和备用源切换。
- 当地时间之外的地图或地理探索。
- 真实音频电平或频谱可视化。
- 深浅外观及已确定语言／更新／About 之外的设置扩展。

仅现代页可进入设置；沉浸页不能进入设置。最新设置项为语言切换、更新检查和 About，使用常见齿轮图标。参考图中的均衡器、变速、快进／快退、FM／AM 切换等不自动成为需求。

后台播放、锁屏／耳机控制是前期技术方案中的方向，具体产品行为与首版验收范围仍需整理确认。

## 当前范围外

后续独立音乐套件承接本地音乐播放、文件导入，以及 Spotify／网易云等外部音乐 App 的状态监听与美化。Aether 当前不因未来复用目标提前加入这些功能。

录音、节目回听、时移缓存、账号同步、付费功能和桌面 Widget 尚未纳入当前规划范围。

## 数据与验证边界

- Radio Browser 是候选目录，不是音频托管服务，也不保证所有地区可播。
- 收录状态、台标、标签和音源地址都可能缺失或变化；播放成功不代表节目元数据完整。
- 具体城市、当地时区、实际节目名和连接状态不得由品牌文案补造。
- 后续自动枚举应记录环境、范围和结果，不把有限地区实测写成全球可用保证。

参考：[Radio Browser 字段与搜索文档](https://docs.radio-browser.info/)、[Radio Browser 接入要求](https://api.radio-browser.info/)、[Android ICY 元数据](https://developer.android.com/reference/androidx/media3/extractor/metadata/icy/IcyInfo)。这些是规划参考，不代表已经完成 API 接入。

当前实现与严格视觉验收按 [Android 交接书](ANDROID-HANDOFF.md)推进。Kotlin 已由用户确定；具体库、数据接入和平台行为需在实现中核对与验证。
